## Section 1 — Purpose and reviewer details

### Form description

We are preparing Phase 1 of a waste collection web application. The goal of this review is to connect each driver-schedule area with the correct mapped collection-site record or records.

The materials include a 670-row collection-site list, the raw driver schedule, a barangay-to-site reference, and a draft schedule-to-site mapping. Some schedule entries use barangay names, streets, landmarks, or operational area labels, so the draft cannot reliably determine every site assignment without GSO confirmation.

Please confirm the official meaning and site coverage of CBD, Market 1–3, RIC 1–2, and Food Waste Collection. The current schedule and site list do not identify firing lines, so we need GSO to distinguish pick-up points, firing lines, route segments, and general coverage descriptions. We will use your answers to link each schedule row to the correct mapped site record or records for Phase 1 of the waste collection web application. Please use the record IDs in the linked annotation spreadsheet and mark uncertain items **Needs verification** rather than guessing. This review is to document current GSO information, not to redesign routes.

**If automatic sharing is configured:** After submission, edit access to the annotation spreadsheet will be sent to the verified account above.

## Annotation spreadsheet structure

Give every source row a fixed ID before sharing: for example, `SITE-0001` through `SITE-0670` and `SCHED-0001` onward. Keep the original source row number in a separate column. Do not rely on “Site 1” as a unique identifier.

Use five tabs:

1. **Site records** — One row per site record, with the original fields plus GSO-confirmed active status, official site/barangay/purok name, site schedule, coordinate correction, line classification, review status, and GSO notes.
2. **Raw schedule** — Preserve all 504 rows as received, with an immutable raw row number; do not overwrite source values.
3. **Schedule review** — One row for each distinct nonblank schedule record (including the 55 with no collection area), linked to its raw row number(s). Keep duplicate count and the current cleaning/mapping result so GSO can say whether repeats are duplicates and fill in missing route areas.
4. **Area/range item review** — One row per place or range component named in the CBD, Market, RIC, Food Waste, and A-to-B schedule text. Include Schedule Record ID, exact source phrase, GSO category (pick-up point / firing line / route segment / landmark or boundary / area label / other), official name, start/end points if applicable, and related Site Record IDs.
5. **Site–schedule assignments** — One row per confirmed relationship, containing a Schedule Record ID and Site Record ID. Repeat a site on additional rows if it belongs to multiple schedules. Include assignment status and notes. This keeps many-to-many relationships unambiguous.

Suggested review statuses: **Confirmed**, **Corrected**, **Not a collection site/route area only**, **Inactive/removed**, **Duplicate**, and **Needs verification**.

## Automatic spreadsheet access

Google Forms can collect a verified respondent email. A Form Submit installable Apps Script trigger can read that email and grant Editor access to the separate annotation spreadsheet with `DriveApp.getFileById(SHEET_ID).addEditor(email)`. The trigger runs under the account that installed it, so that account must be able to edit and share the sheet. Share only the annotation spreadsheet, not the Form response spreadsheet.

Before using automatic sharing, confirm that the respondent email belongs to the intended reviewer and that the owner’s Google Workspace permits external sharing. If collecting a manually typed email, verify it before granting edit access.
